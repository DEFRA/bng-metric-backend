# BNG Service template: field mapping

> Generated by `npm run data-dictionary` ([`scripts/gen-template-mapping.js`](https://github.com/DEFRA/bng-metric-backend/blob/main/scripts/gen-template-mapping.js)).
> Do not edit by hand: change the reader's column mapping ([`src/validation/geopackage/service-template/template-mapping.js`](https://github.com/DEFRA/bng-metric-backend/blob/main/src/validation/geopackage/service-template/template-mapping.js))
> or the column uses beside it ([`src/validation/geopackage/service-template/template-column-uses.js`](https://github.com/DEFRA/bng-metric-backend/blob/main/src/validation/geopackage/service-template/template-column-uses.js)) and regenerate.

How the service consumes each column of version 1.0 of the BNG Service
template, on each table and stage: the field it is stored in, as its path in the
[`data dictionary`](https://github.com/DEFRA/bng-metric-backend/blob/main/data-dictionary/data-dictionary.md), whether the service uses it,
ignores it or refuses the file on it, and what uses it.

160 columns: 110 used, 48 ignored, 2 refused on.

## Reading the mapping

- **Use**: `used`, the service reads the value; `ignored`, it does nothing with
  it; `refused`, it reads the value only to refuse a file on it.
- **Used by**: `calculation`, the biodiversity units; `validation`, a check that
  refuses a file, or an edit, on the value; `display`, the stored value shown
  back to the user.
- **Stored field**: the paths in the data dictionary the value is saved to.
  Every column the service reads is also kept, under its own name, in the
  feature's `properties` open map; a column the reader drops is never
  stored.
- **Stages**: a baseline upload reads the Baseline tables. A baseline +
  post-intervention upload reads every table, and saves the Baseline tables
  as the baseline as it does so.
- Every text column, used or not, is checked at upload for its length and,
  for a drop-down, that the template's list offers the value. That check is
  not listed as a use.

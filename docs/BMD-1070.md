# BMD-1070 implementation and review

An individual habitat without its required calculation inputs saves `units: null`
and `status: Incomplete`. Guards run before the relevant units calculator.
Recalculation clears previous units, including after editing a baseline that a
post-intervention habitat depends on. Valid zero units remain Complete.

## Required inputs

| Calculation          | Required inputs                                                                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Baseline area/tree   | Habitat type/key, condition, measured or legacy area                                                                                                  |
| Baseline hedgerow    | Habitat type, condition, measured length                                                                                                              |
| Baseline watercourse | Habitat type, condition, length, both encroachments                                                                                                   |
| Retained             | Baseline identity/condition and feature size; proposed identity remains complete after import validation                                              |
| Created              | Proposed identity/condition, size, strategic significance, advance and delay                                                                          |
| Enhanced             | Baseline and proposed identity/condition, size, proposed strategic significance, advance and delay; linear calculations also need the baseline length |

Watercourse Retained uses baseline encroachments. Created and Enhanced use
proposed encroachments. Enhanced does not consume baseline encroachments.
Baseline calculations and Retained pricing do not consume timing or proposed
strategic significance. Explicit zero timing is valid; missing timing is not
silently replaced with zero. Imported missing broad habitat already cascades to
missing type under BMD-1059; legacy fully qualified habitat keys remain supported.

Lost area rows retain the existing Created dispatch. Their timing is nulled by
BMD-1060 and therefore their proposed units are null under BMD-1070. Lost linear
features/trees retain the existing import exclusion. Stored legacy Lost linears
represent no proposed habitat and remain Complete with zero units.

## Validation evidence

- `src/services/upload/null-unit-calculation.test.js`: real engine controls and
  spies for all four layers, each required input, stale units, recovery after
  fixing inputs, individual null timing, irrelevant null metadata, explicit
  zeros, missing sizes, failed lookups, mixed totals and baseline resync.
- `src/validation/geopackage/import-combinations-pipeline.test.js`: extraction,
  BMD-1059/1060 cleansing, enrichment and Joi validation, including one or both
  timing values missing and Retained timing exceptions.
- Existing enrichment, edit-service and route tests now assert explicit null
  rather than zero or an absent field for incomplete calculations.
- PostgreSQL import tests verify saved null units/status for BMD-1059 attributes,
  BMD-1060 combinations and timing, baseline uploads and combined PI uploads.
  Edit tests verify the response and persisted document agree.
- The companion harness uses independent workbook inputs and checks null units
  with Incomplete status for every imported habitat. A fabricated zero and a
  perturbed valid calculation must both fail the comparison gate.

No new logging, database migration, project-total semantics or frontend rendering
is included. Existing nullable JSON fields are reused and their dictionary
annotations updated. Existing projects change when recalculated; deployment does
not backfill them. Totals continue to sum available numeric units.
